# Security and operational limits

PDFCraft Studio is self-hosted reference code, not security-certified infrastructure for unknown public traffic. Do not publish anonymously without a security review.

- **Authentication:** scrypt password hashing with per-user salts; SHA-256-hashed random bearer session tokens expiring after 24 hours. Bearer tokens live in browser session storage. Password reset uses SMTP-delivered one-use links (30-minute expiry), hashes reset tokens at rest and revokes existing sessions; reset is unavailable until server SMTP configuration. No MFA or email verification is provided.
- **Authorization:** file metadata is scoped by owner ID; stored filenames are sanitized; ownership is checked on read/delete and signing request retrieval. Accounts and uploads cannot access other users' files in current route tests.
- **Rate limits:** SQLite basic per-IP registration / per-account login / per-token signing counters. These mitigate brute-force misuse but cannot replace API gateway rate controls or bot management.
- **Uploads:** limit 50 MB per file (configurable), 120 MB per processing job, 25 files/job; private vault limited to 300 MB/account by default. Malicious PDF parsing, resource exhaustion, zip-bombs and input sanitization need independent hardening and sandboxing.
- **Stored files:** user documents in `data/vault/<userid>`, signed copies in `data/signatures/<userid>`; filenames and IDs are server-generated. `data/workspace.db` contains identities and hashes. Do not expose this directory via static hosting or share backups publicly.
- **Cloud data:** OAuth authorization code flow with PKCE, short-lived state and encrypted credentials with Fernet. Protect the persisted encryption key. Cloud integration requires independently configured OAuth apps.
- **Remote signing:** signer links grant authority by possession and expire in 1–30 days. The signer name is self-declared. Internal event hash chains are not third-party timestamping, PKI, verified identity or court-admissibility guarantees.
- **PDF confidentiality:** ordinary processing files are removed after HTTP download completes. Saved vault files are stored persistently until deleted. Deleting a document also removes historical signing request metadata; back up first if retention is legally required. Redaction should be verified with independent tools for critical data; the Redact tool now strips metadata, XML metadata, embedded files, annotations and links by default, but independent output inspection remains important (other hidden content and unsupported PDF structures may exist).
- **Remote HTTPS URL conversion:** admin opt-in only; public-IP-only DNS resolution, pinned curl IP, public HTTPS/443, no redirects, proxies, or remote page resource loads. This reduces SSRF risk but does not replace external security auditing, tenant-level rate limits or abuse monitoring.
- **SMTP:** admin must configure dedicated credentials and the canonical public URL; email links are bearer capabilities. Use TLS and a verified sender. Test deliverability before public deployment.
- **Operations:** enforce HTTPS with a reverse proxy, content security policy, file/malware scanning, process/container quotas, isolated workers, antivirus and penetration tests. Run as an unprivileged user with limited filesystem access. Implement proper logging that excludes document text and authorization headers. Set retention/deletion/backup controls and comply with relevant privacy requirements.

**Never commit `data/`, `.env`, OAuth tokens, session tokens, private certificates, or user documents to a repository.**

## v5 signing and comparison additions

- **PKCS#12 signature private keys:** P12/PFX bundles and passphrases are supplied per processing request and used only inside the temporary processing job; do not store or email private key bundles. They are sensitive; use a deployment you personally trust. Temporary files are removed after processing response cleanup, subject to host OS/runtime guarantees. Never upload test or real private keys to public untrusted instances.
- **CMS cryptographic signing:** detached SHA-256 signature of PDF ByteRange with `Adobe.PPKLite`/`adbe.pkcs7.detached` encodings. Existing signed PDFs are refused to avoid silently invalidating signatures through a full-document rewrite. Multiple incremental signatures and long-term PAdES-LTV validation are not implemented.
- **CMS verification:** OpenSSL performs detached signature integrity verification with **no CA trust** (`-noverify`); appended bytes that were not signed are reported distinctly via `covers_entire_file=false`. An additional host-system CA-chain check is attempted separately; it is not Adobe/EU trust-list verification and does not check revocation or prove who signed.
- **Visual compare preview:** temporary raw uploads are bounded by file/aggregate upload-size controls, page index 1–500 and preview image limits. Rendered image base64 stays in the browser for the session and is not persisted in the server vault.
- **Local AI profile:** Ollama/LibreTranslate are optional Docker containers on the private Compose network, no host ports exposed by the profile. Images/models require separate downloads, licensing review, resource limits and appropriate security patching. Pinned image digests should be used for serious deployment.
